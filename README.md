# Todogram

Telegram-бот, который делает чеклисты из сообщений рабочего чата, и мини-приложение для их правки.

[Сайт Todogram](https://todogram.pro/) · [Интерактивное демо](https://todogram.pro/?demo&projects) · [Скачать для Mac](https://github.com/IvanMayorov/todogram-community/releases/download/mac-v0.1.1/Todogram-0.1.1-arm64.dmg)

В демо можно открыть проект, выбрать задачу и отметить пункты чеклиста на примерах без входа в Telegram.

Для Mac с Apple Silicon доступна тестовая версия 0.1.1. [Установка и сборка клиента](desktop/README.md).

[Написать автору в Telegram](https://t.me/ivanmayorov)

## Из чего состоит

| Путь | Что это |
|---|---|
| `app/main.py` | Запуск: бот (long polling) + веб-сервер мини-приложения в одном процессе |
| `app/handlers.py` | Буфер сообщений, реакции ✍️ / ⚡, кнопки чеклиста, команды |
| `app/auto.py` | Автоматический режим: поиск задач в переписке и предложения с кнопками |
| `app/tasks.py` | Сборка задачи: альбомы, медиа, вызов ИИ, отправка и обновление чеклиста |
| `app/ai.py` | ИИ-модель (OpenAI-совместимый API) и расшифровка речи |
| `app/media.py` | Скачивание файлов из Telegram, звук и кадры из видео через ffmpeg |
| `app/web.py` | API мини-приложения: проверка `initData`, доступ только участникам чата, подписанные ссылки на картинки |
| `app/agent_api.py` | API для агента (MCP-сервера): все проекты по `AGENT_TOKEN`, изменения идут тем же путём, что из приложения |
| `app/db.py` | SQLite |
| `webapp/index.html`, `app.css`, `app.js` | Мини-приложение: разметка, стили, скрипт (без сборки; сервер отдаёт их с одной версией `?v=` и сжатием). В Telegram берёт данные из API, в обычном браузере показывает демо |
| `app/live.py` | «Что-то изменилось»: сервер шлёт открытым приложениям сигнал (`/api/live`), и экран обновляется сразу; опрос раз в 30 с — подстраховка |

## Запуск на своём компьютере

1. Создайте окружение и установите зависимости:

   ```bash
   python3.12 -m venv .venv
   .venv/bin/pip install -r requirements.txt
   cp .env.example .env
   ```

   Заполните `.env` (образец — `.env.example`): `BOT_TOKEN`, `AI_BASE_URL`, `AI_API_KEY`, `AI_MODEL`.
2. Запустите:
   ```bash
   .venv/bin/python -m app.main
   ```
3. Мини-приложение доступно на `http://localhost:8787`. Чтобы открыть его в Telegram, нужен HTTPS-туннель:
   ```bash
   cloudflared tunnel --protocol http2 --url http://127.0.0.1:8787
   ```
   Адрес туннеля укажите в `.env` (`PUBLIC_URL`) и в BotFather: `/setmenubutton` и Bot Settings → Configure Mini App.

## Подключение к чату

1. Добавьте бота в группу и **сделайте администратором**, иначе Telegram не присылает ему реакции.
2. Проверьте, что в чате разрешены реакции ✍️ и ⚡.
3. Бот видит только сообщения, отправленные после его добавления.
4. Пересылка: выделите сообщения в чате → «Переслать» → личка бота. Бот соберёт пачку в одну задачу и спросит, в какой проект (если проект у вас один — не спрашивает). У таких пунктов нет ссылок на исходные сообщения: Telegram не говорит боту, откуда переслано.
Проект без чата: «Проекты» → «Новый проект» в мини-приложении. Задачи в него добавляют в приложении или пересылкой сообщений боту в личку (бот спросит, в какой проект), людей зовут ссылкой из «Доступа» — о каждом новом бот пишет создателю в личку. Чеклист никуда не публикуется, задачи живут в приложении. Удалить такой проект вместе с задачами может только его создатель: экран проекта → «Переименовать или удалить».

Связанные задачи: одна тема в разных чатах (например, сертификаты обсуждают и в R&D, и в чате сайта) — на экране задачи «Связать с задачей»: приложение предложит похожие по названию из всех ваших проектов или найдёт по словам. Задачи не сливаются, каждая остаётся в своём чате, но обе показывают друг друга под пунктами; тот, кого нет во втором чате, видит только «Ещё одна — в проекте, где вас нет». Агент в `get_task` тоже видит связанные задачи.

5. Автоматический режим: администратор чата пишет `/auto on`. После паузы в переписке (`AUTO_PAUSE_SECONDS`, по умолчанию 2 мин) бот сам находит задачи и сразу создаёт их или дописывает пункты в открытые. Ошибку исправляют одной кнопкой: «Не задача» под новым чеклистом, «Отменить» или «Отдельной задачей» под дополнением. Вся новая переписка этого чата при этом уходит ИИ-модели. Выключить: `/auto off`.

## Закрытая альфа

Для самостоятельной установки доступ открыт по умолчанию. Чтобы принимать участников по заявкам, задайте `CLOSED_ALPHA=1` и числовой Telegram ID администратора в `ADMIN_ID`. Администратору нужно один раз открыть личный чат с ботом. Без ID бот сохраняет заявки до назначения администратора.

Ссылка `https://t.me/<ваш_бот>?start=waitlist` записывает человека один раз. В личку администратору приходит кнопка «Открыть доступ». Команда `/alpha` показывает ожидающие заявки, в том числе поданные ранее. Бот отправляет приглашение по Telegram ID. При первом включении сохраняется доступ ранее активных пользователей и подключённых групп.

## Запуск через Docker

```bash
docker compose up -d --build
```

Данные лежат в `./data` (база и кэш картинок). Перед контейнером нужен reverse proxy с HTTPS (Caddy или nginx + Let's Encrypt) на порт 8787.

## MCP для агентов

`mcp_server/checklists.py` — MCP-сервер: агент (Claude Code и др.) видит задачи и отмечает выполненные пункты.
Отметки идут через бота, поэтому чеклист в чате обновляется сразу.

Файлы из отмеченных сообщений (таблицы, PDF, архивы) сохраняются в задаче: в приложении раздел «Файлы», файл до 20 МБ скачивается через бота, файл больше — открывается сообщение в чате.

Срок задачи и напоминания (`app/deadlines.py`): срок ставит ИИ по сообщениям, человек в приложении или агент (`set_due`). Напоминания личные — за день, за час, в момент срока (для срока без времени — накануне и в день срока в 10:00), приходят в личку с кнопками «Через час» и «✅ Сделано». Время — по `TZ` из `.env`.

Картинка проекта: экран проекта → «Картинка проекта». Своя картинка видна в Todogram поверх фото чата (сам чат не меняется), убрать — снова фото чата.

Время: чип «Время» на экране задачи — сколько потрачено, можно отмечать по ходу (кнопки +15 мин … +2 ч прибавляют) и при закрытии. Каждое изменение пишется в журнал (кто, когда, сколько); «Проекты» → «Время» — итоги за неделю, месяц, квартал, всё время или свой диапазон дат по проектам, людям и задачам, с фильтрами. В чеклисте в чате у незакрытой задачи — «потрачено N ч».

Исполнитель: в приложении — при создании задачи или чипом «Исполнитель» на экране задачи (список — те, кого бот видел в проекте, и люди из других проектов того, кто назначает: такой исполнитель видит только эту задачу и только пока он на ней исполнитель: не может сменить исполнителя, убрать задачу в архив или удалить её), у агента — `assign_task` или `assignee_id` в `create_task`. Исполнителю приходит сообщение в личку, в чеклисте в чате появляется «👤 Имя». Все напоминания, которые кто-либо поставил на задачу, приходят и исполнителю. «Взять в работу» без исполнителя делает исполнителем того, кто взял.

Инструменты: `list_projects`, `list_tasks`, `get_task` (пункты, описание, комментарии/вопросы, история, исходные сообщения, скриншоты),
`create_task` (чеклист сразу публикуется в чате; можно сразу задать `descr`), `edit_task` (название, описание, архив, отчёт),
`delete_task`, `move_task` (любой проект ↔ любой, в т.ч. «Без проекта»), `add_items`, `rename_item`, `delete_item`, `reorder_items`,
`set_due`, `set_reminders`, `list_people`, `assign_task`, `mark_item_done`, `complete_task` (с опциональным отчётом),
`take_task`, `set_task_status`, `list_comments`, `add_comment`, `edit_comment`, `delete_comment`, `resolve_question`,
`search_tasks`, `create_project`, `rename_project`.

- Доступ — по `AGENT_TOKEN` из `.env` (полный доступ ко всем проектам, держите в секрете). Пустой токен выключает API агента.
- Пример подключения MCP-сервера:
  ```bash
  claude mcp add checklists -s user -e CHECKLIST_URL=http://127.0.0.1:8787 -- "<путь>/.venv/bin/python" "<путь>/mcp_server/checklists.py"
  ```
- Когда бот будет на сервере, `CHECKLIST_URL` — его HTTPS-адрес, а `AGENT_TOKEN` передаётся через `-e AGENT_TOKEN=...`.
